# Ponke feature audit — 24 September 2026

This audits the original Ponke request against code, automated tests, and live checks. "Implemented" means the application path exists and was exercised with controlled dependencies; it does not imply that a personal Google account or real financial records have been connected.

| Original feature | Implementation and verification | Remaining live step |
| --- | --- | --- |
| Personal Chief of Staff | Structured intent router, bounded conversation context, typed action dispatch, clarification and confirmation; routing and failure tests pass. A real Gemini reminder intent resolved the requested local time. | Try several natural-language requests in the private bot chat. |
| Telegram interface | Text, JPEG/PNG receipts, private-chat allowlist, inline confirmations, document export, rate limiting and polling; authorization and delivery tests pass. Bot token was validated and local service is healthy. | Confirm replies and document delivery from the user's own Telegram account. |
| Google Calendar | OAuth 2.0 PKCE, encrypted tokens, create/read/search/update/delete, conflict checks and timezone conversion; mocked integration and acceptance tests pass. | Create a Google OAuth Web client, register the configured callback, connect in Telegram and verify real events. |
| Reminders and tasks | One-time and recurrence-rule reminders, completion/cancellation, durable delivery queue and daily scheduler; acceptance and recurrence tests pass. | Send a short-lived reminder and observe Telegram delivery. |
| Personal finance | Accounts, categories, merchant corrections, transactions, IDR shorthand, deterministic summaries, manual balances, Excel and CSV export; finance/export acceptance tests pass. | Enter disposable records and check the resulting amounts and workbook. |
| Receipt extraction | Image validation and metadata stripping, vision schema, confidence clarification, multi-signal duplicate detection, reviewed override; mocked vision/receipt tests pass. | Submit a real receipt; extraction accuracy depends on image quality and model behavior. |
| Investment analysis | Assets, holdings, user-reported trades, manual prices, allocation and partial net worth; investment questions route to the council. Decimal and liability tests pass. | Add manual accounts/holdings/prices. Live market prices are deliberately absent in this MVP. |
| Multi-agent Decision Council | Four separate specialists, two concurrent rounds, Chief Analyst with contextual weights, concise verdict and persisted opinions; PostgreSQL acceptance tests pass. A harmless live Gemini run completed all nine calls. | Try a real decision after entering the financial facts it should consider. |
| Long-term decision memory | Decisions, both rounds of opinions, history/details and outcomes are stored per user; retrieval tests pass. Automatic specialist calibration is disabled until there is enough outcome data. | Record a real decision and follow up with its outcome. |
| Lightweight Personal Analyst and daily briefing | Evidence-labelled finance insights, decision outcomes, reminder completions, recorded calendar changes, user-reported trade and question counts; configurable daily Telegram briefing with partial-failure handling. Tests pass. | Add normal activity, then request an analysis and observe the next scheduled briefing. |

The user's later choice of a free model changed the default from GPT-6 Astra to Gemini 3.5 Flash-Lite. OpenAI remains configurable. Google Calendar needs separate OAuth credentials; a Gemini key cannot authorize a personal calendar. Live financial and receipt interpretation were not asserted from mocks. The app is currently running locally; 24/7 operation requires keeping this computer on or deploying the Docker stack to a server.
