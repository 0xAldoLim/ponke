# Ponke delivery checklist

## COMPLETED BY CODEX

- Modular Python/FastAPI service, Telegram private-chat allowlist and rate limits.
- Structured Gemini routing with configurable primary/fast models and optional OpenAI support; no keyword-only intent classifier.
- PostgreSQL models, immutable Alembic migration, pinned dependencies and Docker Compose.
- Google OAuth with PKCE, single-use state and encrypted tokens; calendar create/query/search/update/delete and conflicts.
- Durable one-time/recurring reminders, completion/cancellation and retrying Telegram outbox.
- Expense/income records, Indonesian monetary shorthand, traceable raw input, editable categories and merchant overrides.
- Receipt vision extraction, image validation, duplicate protection, clarification and reviewed overrides.
- Decimal financial analytics, eight-sheet Excel export and CSV export with formula-injection protection.
- Account/holding/trade/manual-price snapshots, liability-aware reported net worth and provider interface.
- Four council specialists, two rounds, contextual judge weights, persisted decisions, details and outcome records.
- Bounded conversation memory, explicit preferences, evidence-based analyst and daily briefing.
- Setup, deployment, backup/restore helpers, automated tests and PostgreSQL CI.

See VERIFICATION.md for the actual test results and what still needs live validation.

## WHAT I MUST CREATE

- A Telegram bot in BotFather.
- A Google AI Studio Free Tier project and Gemini API key. An OpenAI API project is optional.
- A Google Cloud project with the Calendar API and Web application OAuth client.
- A local `.env` copied from `.env.example`.
- For deployment, a Linux server with Docker and an optional HTTPS domain for Google authorization from your phone.

## CREDENTIALS I MUST PROVIDE

In `.env` only:

- `TELEGRAM_BOT_TOKEN` from BotFather.
- `ALLOWED_TELEGRAM_USER_IDS` from the included ID helper.
- `AI_PROVIDER=gemini` and `GEMINI_API_KEY` from Google AI Studio.
- `GEMINI_PRIMARY_MODEL=gemini-3.5-flash-lite`; optionally tune `GEMINI_REQUESTS_PER_MINUTE` to your active quota.
- For optional OpenAI usage only: `AI_PROVIDER=openai`, `OPENAI_API_KEY`, and selected OpenAI models.
- `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` from your Google OAuth client.
- `APP_SECRET_KEY` generated by `python scripts/generate_key.py`.
- A strong `POSTGRES_PASSWORD`, repeated correctly in `DATABASE_URL`.

No real credentials are committed. Keep each installation's credentials in its ignored local `.env`.

## COMMANDS I MUST RUN

From the cloned repository on Windows:

```powershell
Copy-Item .env.example .env
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-dev.lock
.\.venv\Scripts\python -m pip install --no-deps -e .
.\.venv\Scripts\python scripts/generate_key.py
# Fill .env with the Gemini key; send /start to your bot before the next helper.
.\.venv\Scripts\python scripts/telegram_user_id.py
# Put your numeric ID in .env, then:
docker compose up -d --build
docker compose ps
```

For Linux/macOS use `cp` and `.venv/bin/python`. Keep Compose's database hostname `db`. See README for a locally running Python app with Docker PostgreSQL.

## GOOGLE SETUP I MUST COMPLETE

1. Enable Google Calendar API in your Cloud project.
2. Configure consent/audience; add yourself as a test user when using Testing.
3. Add scope `https://www.googleapis.com/auth/calendar.events`.
4. Create a Web application OAuth client.
5. Register exactly `http://localhost:8000/oauth/google/callback` locally, or your deployed HTTPS equivalent.
6. Fill the client ID, client secret and matching redirect URI in `.env`, then restart Ponke.
7. Send `/connect_calendar` in Telegram, open the link on a computer that can reach the callback, and authorize your Google account.

## TELEGRAM SETUP I MUST COMPLETE

1. Open verified @BotFather; send `/newbot`.
2. Pick a name and bot username; copy the token into `.env`.
3. Send your new bot `/start`.
4. Run `scripts/telegram_user_id.py` while Ponke is stopped; allowlist your ID.
5. Start Ponke and interact in a private chat. No webhook setup is required.

## HOW TO TEST EACH FEATURE

Run `python -m pytest -q`, `python -m ruff check .` and `python -m ruff format --check .` in the virtual environment. Then follow the live A–I table in README: reminder delivery, calendar creation, IDR expense, receipt/duplicate, category totals, export, council decision, decision retrieval and timezone-correct calendar query.

Additional live checks: cancel a confirmation, try an unauthorized Telegram ID, complete a recurring reminder, manually set an account and holding, request a briefing, and reconnect Google after revocation. Use disposable test entries and inspect Google Calendar directly.

## HOW TO DEPLOY IT

Use the README's single-VPS Docker Compose path. Keep PostgreSQL private, run one app replica, configure HTTPS for the Google callback, retain the encryption key and establish encrypted off-host backups. The repository does not provision a server, DNS or paid services.

## KNOWN LIMITATIONS

Live API authorization and real model interpretation remain your final acceptance step. Market data is manual; no banking sync, brokerage orders, FX, PDF/voice ingestion or recurring-calendar editor exists. Financial snapshots need reconciliation. Delivery is at-least-once; a crash may produce a duplicate reminder or an uncertain in-flight request. Read the README's detailed limitations before relying on automated reminders or financial interpretation.
